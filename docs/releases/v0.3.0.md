# Frame v0.3.0

Frame v0.3.0 gives installation authority, binding preparation, process exit and
business settlement explicit owners. It contains breaking Go API, SDK, stdio
protocol and private persisted-state changes from v0.2.0.

## Requirements

The Go minimum is declared in `go.mod`. This release requires Go 1.27.4 or newer,
which includes the standard-library fix for
[GO-2026-6859](https://pkg.go.dev/vuln/GO-2026-6859). CI reads that same minimum.
The SDK declares its supported Node range in `sdk/package.json`; its current
minimum is Node 24.22.1. The optional React entry targets React 19. Managed local
execution requires supported Unix filesystems and local sockets.

## Changes

- Separate plugin Host policy in `host`, callable contracts and lifetimes in
  `frame`, and JSON/schema admission in `value`. Remove the `portable` package
  and forwarding APIs.
- Compose a durable Host from one `Authority`, owning its admission gate, epoch,
  installation persistence and execution protection. Restoration reads that
  original authority under the same admission as projection; caller-held
  installation records cannot overwrite a later commit.
- Retain actual instance start claims and original Work through preparation.
  Withdrawal starts the original retirement with membership removal. Close joins
  actual exit, durable settlement and reference release without replacing any
  of those conclusions with cancellation or diagnostic counters.
- Keep the Store writable after a confirmed rollback caused by cancellation or
  statement failure. Unknown commits, unconfirmed connection disposal, corrupt
  execution records and SQLite corruption still require recovery. Business
  owners can persist their terminal receipts after a definite rollback.
- Distinguish `runner.ErrUnavailable` for an original child that cannot attach
  from `frame.ErrClosed` for runner shutdown. Preserve runner identity, epoch,
  original Wait and exact exit-receipt checks on both attachment channels.
- Derive stdio protocol identity from its declarations and message shapes. Use
  strict, consistent JSON encoding for wire, storage and identity projections.
- Make resource acquisition part of the SDK Lifetime that owns it. Keep browser
  connection and release conclusions explicit, including crash and reconnect
  recovery.

## Upgrade from v0.2.0

Upgrade the Go module, Host, runner, SDK and plugin implementations together.
Regenerate application contracts and browser control projections with the new
owners. There is no old-protocol adapter or automatic private-state migration.

| v0.2.0 surface | v0.3.0 replacement |
| --- | --- |
| Root `frame.Host`, `HostConfig`, `NewHost` and plugin authoring APIs | `host.Host`, `host.Config`, `host.New` and the corresponding `host` APIs |
| `portable` callable contracts and methods | Root `frame` capability, method, invocation and typed-call APIs |
| `portable/contractgen` and portable value admission | `contractgen` and `value` |
| Pointer handles such as `*frame.Work`, `*frame.Setup` and `*sqlite.Store` | Value handles; use `Valid()` to distinguish an issued handle from its zero value |
| Separate Host admission, epoch, installation and protection options | `host.Config{Authority: store}`; a plain `host.Admission` is volatile |
| `Host.Restore(ctx, records, plugins)` | `Host.Restore(ctx, plugins)` with the original durable authority |
| `ImportDeclaration.Providers` | Declare imports separately; fixed routes belong to `UnitDeclaration.Fixed`, resolved routes to `ImportBinding` |
| Installation records containing unit declarations | Restore the exact `Plugin` for each retained release; it owns those declarations |
| `CommitSucceeded`, `CommitRejected` | `host.Committed`, `host.NotCommitted`; inspect the original commit conclusion |
| `Candidate.Metadata()` | The decoded `Candidate.Metadata` field; handle errors when obtaining typed candidates |
| `Use.BeginClose` | `Use.Close` for complete retirement; `Use.Lifetime().BeginClose` observes physical exit only |
| SDK standalone `acquire`, `withResource`, `AcquiredResource` | `Lifetime.acquire`, `Lifetime.withResource`, `Acquired` |
| Attachment exit reported as `frame.ErrClosed` | `runner.ErrUnavailable`; runner control replies use `unavailable` |

Execution-protection approval and attempt recording return `(host.CommitState,
error)`. Use that original state when deciding whether durable settlement is
required. An error alone does not prove that a write committed or rolled back.

Captured bindings retain exact physical roots. A portable value can still be
borrowed across Realms, but a capture whose provider graph cannot be rebuilt in
its original Realm cannot become a durable binding snapshot. Recreate those
business bindings from an admissible capture before retaining them.

The stdio hello now exchanges a derived `protocol` digest. Release manifests and
locks drop `schemaVersion`; binding snapshots drop `FormatVersion` and use a typed
`Selection` digest. Private SQLite JSON members and submission states, and the
runner journal shape, also changed. Mixing these records or components with
v0.2.0 is unsupported.

### Existing development state

1. Stop admitting new operations and let each original business owner settle
   its accepted work.
2. Close Uses and original execution owners. Confirm actual release and durable
   settlement before replacing any state directory. Keep unresolved owners and
   their evidence available until they conclude.
3. Preserve any application data or audit evidence that must survive. Frame
   does not migrate application-owned business schemas or records.
4. Start the upgraded components with fresh Frame and runner development state.
   Restore application-owned state through its own supported lifecycle.

## Install

```sh
go get github.com/Tangerg/frame@v0.3.0
go install github.com/Tangerg/frame/cmd/frame@v0.3.0
go install github.com/Tangerg/frame/cmd/frame-runner@v0.3.0
npm install ./frame-sdk-0.3.0.tgz
```

The GitHub release contains the single SDK tarball, original Chinese design
proposal and `SHA256SUMS`. Check those sums before installing downloaded assets.
The original design proposal is historical; current contracts are defined by
the implementation and package documentation.

## Qualification

`make tools` builds the pinned linter and vulnerability scanner with the selected
Go toolchain. `make check` includes Go races, vet, lint and vulnerability scanning,
SDK types, lint, formatting, tests and installed-tarball consumers. Release
qualification also covers generation consistency, example and command builds,
the independent Go module consumer, real browser recovery and declared Flame
MCP interoperability fixtures. Review the verification report alongside the
prepared assets for actual results and any remaining publication work.
