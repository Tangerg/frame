# Ownership and boundary audit, 2026-11-04

## Baseline and scope

This audit starts from `Tangerg/frame` main commit
`9f51728aa3240394445d87946c1ab9ca57b20968`, tree
`0f467f3b496ff0edbfcbdedcc3b68f03beae017d`. The GitHub connector supplied
the authoritative tree and missing file contents. Every local blob was checked
against that tree, including reused immutable bytes; the reconstructed Git tree
matches exactly. This is an isolated local checkout, not a claim to have fetched
the repository's full Git history. No remote branch, commit or PR was changed.

The baseline contains 436 tracked files and 365 Go/TypeScript source and test
files, totaling 68,297 lines in those languages. Review covered the core Host,
Admission, Lifetime, binding, catalog and Use owners; portable contracts and
value codecs; SQLite; distribution; process, runner and MCP; the browser bridge
and Node/browser/React SDK; examples, generators, packaging and CI. Parallel
reviews followed responsibility boundaries, followed callers across those
boundaries, and independently reviewed risky ownership and protocol changes.

The instructions were `AGENTS.md`, `PROJECT_RULES.md`, `DEVELOPMENT.md` and the
user's stricter ownership, naming, comment and breaking-change requirements.
Earlier remediation reports describe earlier baselines; their findings are not
counted again here. File coverage does not mean every possible execution or
failure schedule has been tested.

The audit confirms and repairs **20 additional correctness findings**: eight
P1, eleven P2 and one P3, plus the structural changes listed below. Each finding
has targeted regression evidence; F-014 separately identifies the concurrency
trace and the narrower deterministic ordering regression.

## Priority definitions

- **P1:** reachable failures in ownership, release evidence, admission or operation
  conclusions that can strand resources or accept an unproved conclusion.
- **P2:** narrower boundary, integrity, capacity or declaration-identity defects.
- **P3:** a valid-looking extreme configuration that cannot be implemented as
  represented, or a smaller maintainability issue.

These are repair priorities, not CVSS scores. Corrupted-storage and mutable-input
cases are described by their exact preconditions, not presented as demonstrated
remote exploits.

## Confirmed correctness findings

### F-001 — P1: copying Work created a second completion authority

Original owner: `Lifetime`'s admitted work interval. Original implementation:
`lifetime.go`, `Work`, `Finish` and `Own`.

`Work` contained its own `finished` flag and was itself the key in the Lifetime's
work map. Copying `*work` copied the flag but not the original map entry. Finishing
the copy failed to return the original interval's capacity. Finishing the
original and then acquiring a resource through the stale copy admitted work
after completion. A value copy therefore created a competing transition.

`Work` is now a handle to one private `workInterval`. All copies use the same
map key, finished flag, context and consumer-hold decrement under the original
Lifetime mutex. The interval implementation is in `work.go`; no reconciliation
rule or second completion counter was added.

Evidence: `work_identity_test.go`,
`TestWorkCopiesShareTheOriginalInterval` and
`TestFinishedWorkCannotBeReopenedThroughACopy`. Both failed against the original
implementation and pass after the fix.

### F-002 — P1: a panicking Use approval stranded initialization and protection

Original boundary: `use.go`, `acquirePrepared` and `protectUse`.

If the configured protection adapter panicked in `ApproveUse`, initialization
never closed. Retirement waited forever, provider holds remained live, and the
Host did not fence new work despite having no conclusion about the durable
approval. Catching the panic outside Frame did not restore those invariants.

Initialization now closes on every unwind. An unpublished Use starts its
original close, and an interrupted approval requires recovery while still inside
the admission gate. The original panic propagates. The fix does not fabricate a
release proof or assume that the interrupted persistence call rolled back.

Evidence: `use_admission_panic_test.go`,
`TestPanickingUseApprovalReleasesLocalHoldsAndFencesAdmission`. Before the fix,
the recovery assertion and bounded Host close failed. The regression now checks
the original panic, closed admission and actual local retirement.

### F-003 — P2: a Host-owned Use consumed two resource records

Original boundary: `use.go`, `publishUse`.

The Use was registered in its owner Lifetime and in the Host Lifetime even when
those were the same object. One actual Use consumed two entries, and a limit
sufficient for an instance plus its Use rejected a valid `StartUnit`.

When the two owners are identical, one original resource handle now carries the
instance dependency edges. Distinct owner and Host lifetimes still receive the
necessary independent retention edges. Retirement already supports a missing
second handle; no extra boolean tracks this case.

Evidence: `use_resource_test.go`,
`TestHostOwnedUseConsumesOneResource`, reproduced at `MaxResources == 2`.

### F-004 — P2: invalid Use identities reached plugin preparation

Original boundary: `use.go`, `useConfig`.

Malformed Realm and execution identities could start setup before a later
protection boundary rejected them. Validation was too late to guarantee that an
invalid request had no plugin-side preparation effects.

After inheriting a parent's authority, `useConfig` now validates the optional
Realm and execution identities before preparation. The complete durable
approval invariant is owned by `UseApproval.Validate`, shared by Host and Store.
The Store separately checks the current epoch because that is its authority fact.

Evidence: `use_validation_test.go`,
`TestInvalidUseIdentityIsRejectedBeforePreparation`. Both invalid cases invoked
one setup before the fix; both now fail before setup.

### F-005 — P1: durable protection mutations bypassed request integrity

Original boundary: `sqlite/attempt.go` and `sqlite/use.go` settlement, duplicate
admission and parent-admission paths.

Some paths read only request/state/proof columns, omitting the stored
`request_digest`. A corrupted protection record could be accepted as an
idempotent approval or changed to released without establishing that it was the
original admitted request. Ordinary record listing did validate the digest, so
behavior depended on the access path.

`protectedRecord.scan` in `sqlite/protection_record.go` now checks the digest
before semantic decoding. Record reads, duplicate successes, delegated-parent
admission and all three settlement paths use that same boundary. A failed
integrity check cannot advance the stored state and requires recovery where the
operation previously relied on protection.

Evidence: `sqlite/protection_integrity_test.go`,
`TestProtectionSettlementValidatesOriginalRequest` and
`TestProtectionApprovalValidatesOriginalRecord`, covering the affected paths.

### F-006 — P1: invalid protection evidence could claim an original exit

Original boundary: stored Attempt/Use decoders and `AttemptRecord.ExitProven`.

Incomplete or misbound proofs could survive recovery decoding: missing proof
kind, exit identity or evidence, and an execution or Realm different from the
original record. A zero `AttemptRecord` could claim that exit had been proved.
Request invariants also needed checking after durable decoding, not just before
initial insertion; a self-parent attempt with a valid request digest is still
semantically invalid.

The shared decoders now validate the admitted request, stored identity, allowed
state/proof combination and proof relationship. `ExitProven` requires a real
handoff/released state and evidence for that same attempt and Realm.
`Attempt.Validate` explicitly rejects self-parenting. A handoff becoming
released continues to require the original proof bytes.

Evidence: `TestStoredAttemptProofMustProveItsOriginalExit`,
`TestStoredRealmUseProofMustMatchItsOriginalExecution`,
`TestAttemptWithoutProvenStateDoesNotClaimExit` and
`TestStoredAttemptCannotDelegateToItself` in the same regression file.

### F-007 — P1: a cached-import Trust panic leaked its original lease

Original boundary: cached-release publication in `distribution/store.go`.

The cached path acquired a lease before invoking application trust policy.
Cleanup was conditional on a returned error, so panic skipped lease release.
Removal then reported `ErrInUse`, and Store shutdown remained pending.

The publication owner now defers release until successful ownership transfer.
Panic still belongs to the caller's trust function, but cannot silently abandon
the lease the Store acquired. There is no replacement lease or retry policy.

Evidence: `distribution/publication_panic_test.go`,
`TestCachedTrustPanicReleasesOriginalLease`; the original implementation failed
removal and timed out during close.

### F-008 — P2: cached-release verification skipped part of the path policy

Original boundary: cached-tree validation in `distribution/store.go`.

The verifier skipped directories. Invalid empty-directory names and directory
counts outside the admitted archive limit could survive cache inspection. It
also accepted special file modes that the archive policy should refuse.

`artifactVerifier` now admits every path through the shared `pathInventory`
owner, including directories and implicit ancestors, and rejects dangerous
special modes. The limit is accurately named `Limits.Entries`, since it counts
more than regular files. Imported and cached trees use the same policy.

Evidence: `distribution/cache_validation_test.go`,
`TestCachedTreeRevalidatesPathsAndCapacity`, including an invalid empty directory,
excess entries and a setuid file. These cases were accepted before the fix.

### F-009 — P2: a held lease did not revalidate artifact executability

Original boundary: `Lease.Read` and the bounded regular-file reader.

After a lease had been acquired, changing a cached artifact's executable bit
did not change its size or digest. Reading it could succeed even though the
manifest's execution property no longer described the file being read.

The reader captures bytes and permissions from the same opened physical file,
checks that it was not replaced or changed during the read, and returns a
private `fileSnapshot`. `Artifact.verify` owns comparison of size, digest and
executable status. Both cache verification and lease reads consume that same
rule; special modes are rejected at the actual read boundary too.

Evidence: `TestLeaseReadsRevalidateArtifactExecutability` covers both adding and
removing executable permission after acquisition.

### F-010 — P1: Daemon.Close could not advance retained shutdown

Original boundary: `process/runner/daemon.go`, `closeOriginal` and `Close`.

The runner CLI intentionally retains its original Server and directory lock
when an exit-journal write fails. After restoring the failed resource, another
signal can continue that original shutdown. Daemon sent one interrupt and then
waited forever; `closeOnce` prevented later `Close` calls from requesting the
required next step.

One original shutdown worker now accepts subsequent explicit Close requests
and signals the same process. Every caller still joins the same original Wait.
There is no timer retry, replacement daemon, new exit identity or second
completion owner. A failed signal is reported without abandoning the retained
process.

Evidence: `process/runner/daemon_retirement_unix_test.go`,
`TestDaemonCloseCanAdvanceItsRetainedOriginalShutdown`, using a real child with
a deterministic two-signal protocol and no socket dependency. It failed after
five seconds on the original code.

### F-011 — P2: MCP syntax admission allowed lossy or ambiguous JSON

Original boundary: `process/mcp/transport.go`, before SDK decoding.

`encoding/json.Valid` with a UTF-8 byte check still accepts duplicate object
members and unpaired escaped UTF-16 surrogates. Subsequent SDK decoding can
collapse duplicate identities/schema keywords or replace malformed string
content before Frame sees it.

The complete bounded message now passes `jsontext.Value.IsValid`, the strict
standard-library syntax boundary already used by Frame values. The MCP SDK
continues to own JSON-RPC interpretation. Exact number lexemes and valid
surrogate pairs remain supported.

Evidence: the expanded transport corpus rejects duplicate `id`, duplicate
schema `type` and a lone surrogate under whole-line, byte-wise and short-read
segmentation. All nine invalid cases were accepted before the fix; positive
number, surrogate-pair and boundary-size controls remain covered.

### F-012 — P2: runner program text was admitted or encoded lossy

Original boundary: `process/runner/runner.go` program admission and
`process/runner/transport.go` control encoding.

Invalid UTF-8 arguments/environment could reach running state, and v1 JSON
encoding could silently replace bytes with U+FFFD. Program identity encoding
could then collapse invalid text with a legitimate replacement-character
string. NUL arguments and paths could reserve an attempt before the operating
system refused the impossible launch.

One `validProgramText` boundary admits only UTF-8 without NUL before reservation.
The strict control writer rejects unencodable values before writing bytes.
Existing valid request-digest representation remains unchanged; no error
diagnostic echoes environment secrets.

Evidence: `process/runner/launch_admission_test.go` covers invalid path, argument
and environment admission, no-reservation/no-write behavior, legitimate U+FFFD
and non-BMP text, and a socket-free real-child control exchange that preserves
absent, empty and explicit environments without inheriting parent credentials.

### F-013 — P3: the executable byte limit overflowed its reader bound

Original boundary: runner configuration and executable verification.

`MaxExecutableBytes == math.MaxInt64` was accepted, but adding the extra byte
needed to detect overflow produced a negative reader limit. The configuration
could not represent its advertised bounded read.

Configuration resolution now refuses that unrepresentable value before creating
an authority directory. This does not change the separate distribution reader,
which already supports the full positive range with a separate extra-byte probe.

Evidence: `TestExecutableLimitRejectsOverflowBeforeCreatingAuthority`.

### F-014 — P1: browser parent proof read descendants before fencing admission

Original boundary: `browser/proof.go`, `releaseUseTree`.

The original flow read durable children before fencing the live parent. A child
could be admitted and disappear from the operation map in the intervening
window, leaving the release walk without its original browser resource and
causing parent retirement to wait indefinitely.

The bridge now snapshots and fences the live descendant closure under its
existing mutex, joins in-flight admissions, and only then reads the durable
projection. One delegation traversal is used for the live and durable sets;
neither projection becomes an independent authority to admit descendants.

Evidence: `browser/proof_order_test.go`,
`TestUseProofFencesLiveDescendantsBeforeReadingProjection`, proves fencing of
parent, child and grandchild before a deliberately unavailable projection read,
while leaving an unrelated Use open. The original code failed all three
descendant-fence assertions. The broader race is established by the
traced interleaving; this test does not claim to reproduce every scheduling
step through the entire HTTP stack.

### F-015 — P2: typed-nil browser adapters passed construction

Original boundary: `browser.NewBridge`.

An interface containing a nil `ModuleSource` or `RemoteSource` pointer is not a
nil interface. The original checks could accept it, moving failure into later
execution instead of rejecting an invalid adapter at composition.

The constructor now uses the project's existing typed-nil admission helper.
There is no reflection registry or alternative adapter-dispatch path.

Evidence: `browser/config_test.go`, `TestBridgeRejectsTypedNilAdapters`.

### F-016 — P1: HTTP success bodies were trusted without contract validation

Original boundary: `sdk/src/browser/http.ts` and browser response encoding.

Successful status codes with valid but malformed JSON were cast to the declared
TypeScript output type. Missing acknowledgement shape, an invalid Ready result,
or malformed nested Poll data could be treated as a valid mutation result or
permission response. A TypeScript assertion did not validate the wire boundary.
The actual Go v1 encoding could also emit nil slices as null despite generated
array contracts.

Executable response decoders are now generated from the existing Go control
method declarations, field model, enum definitions and codec models. The HTTP
adapter checks success and problem bodies before consuming them. Invalid
mutating responses retain unknown-outcome semantics; invalid query responses
report unavailability. A wire null acknowledgement maps to TypeScript void.

`marshalControl` in `browser/wire.go` supplies the same JSON v2 encoding policy
to HTTP, capacity, wire equality, copying, digests, durable receipts and proofs.
It preserves deterministic ordering and HTML/JavaScript escaping while encoding
empty arrays consistently. Maximum-length HTML-sensitive, quote and backslash
identities are checked against the actual SQLite proof budget. This is a
protocol-boundary repair, not a second handwritten schema.

Evidence: `sdk/src/browser/http_validation.test.ts` and HTTP tests cover missing,
false, null, extra-member, enum and nested-shape cases, including mutation/query
failure classification. Actual Handler output is checked against the generated
decoder, and a no-export plan is admitted after decoding that output. Fifteen
initial SDK cases failed before repair: fourteen malformed successes and the
null-to-void acknowledgement. The actual Handler integration independently
failed on its original null exports array.

### F-017 — P2: sparse arrays bypassed Node portable budgets

Original boundary: `sdk/src/node/limits.ts`.

`Array.forEach` skipped holes, while serialization represented those positions
as null. Node could count fewer nodes or less equality work than it would
actually serialize and validate.

The bounded traversal now reads array positions by index, capturing the same
positions that will be encoded. Sparse entries cannot escape the budget.

Evidence: `sdk/src/node/sparse_json.test.ts` exercises sparse node-limit
admission, nodes/depth/weight/equality parity and null semantics. It does not
claim to isolate a byte-only overflow.

### F-018 — P2: a custom array iterator changed serialized identity

Original boundary: `sdk/src/json.ts`, JSON serialization.

`Array.from` consumed an overridden iterator. An array whose indexed elements
were `[1, 2]` could serialize as `[3]`, diverging from indexed validation and
resource accounting. The iterator could therefore become a second content
authority for one JSON value.

Serialization now uses indexed array positions, matching the bounded traversal
and ordinary JSON array semantics. No caller-supplied iterator participates in
the value's wire identity.

Evidence: the custom-iterator regression in `sdk/src/json.test.ts`.

### F-019 — P2: schema getters supplied different facts to validation and identity

Original boundary: `sdk/src/node/contract.ts`, `schema.ts` and `limits.ts`.

Method construction checked the incoming descriptor, separately froze it,
compiled from the original again and hashed the original again. Schema
compilation similarly budgeted a value and later serialized a fresh read.
A changing getter could make the retained descriptor, validator and digest
describe different schemas, or replace the bounded input after the budget check.

The existing bounded JSON traversal now captures a detached value in the same
walk. Contract checking, schema compilation, retained descriptors and identity
consume that captured value. Rich contract objects own their invariant without
adding a generic cloning or schema framework.

Evidence: `sdk/src/node/schema_capture.test.ts`; four changing-getter
regressions failed before the fix. Positive portable-profile cases also run
against the new capture path.

Final review also exercised an object with `ExactNumber.prototype` and a
changing `text` getter. Reading the lexeme once for retention but rereading the
object for byte measurement still admitted 1,048,591 captured bytes against a
1,048,576-byte limit. The numeric meter now consumes only the captured ASCII
lexeme. A fifth regression rejects that 15-byte overrun, accepts the exact byte
boundary and requires one source read in both cases. Constructed ExactNumber
instances were already frozen; the regression explicitly covers the forged
prototype shape admitted by the existing runtime number predicate.

### F-020 — P2: an event route reread a mutable grant after validation

Original boundary: `Runtime.route` in `sdk/src/browser/runtime.ts`.

The caller could replace `RouteGrant.use` while `validateRoute` was awaiting a
reply. The runtime would then materialize and validate a different valid Use
from the one sent across the route authority boundary. Successful validation
did not refer to a stable input throughout the operation.

The route boundary now captures the grant before the first asynchronous
validation. The same immutable grant is validated and materialized. This uses
the shared JSON capture utility instead of a route-specific identity copy or
post-hoc reconciliation rule.

Evidence: `sdk/src/browser/runtime.test.ts`,
`materializes the route grant that crossed its validation boundary`. Replacing
the caller's Use during the controlled await made the original implementation
validate the replacement; the fixed implementation uses the original grant.

## Ownership and structural remediation

The correctness fixes above are accompanied by related structural repairs:

| Subject | Decision and reason |
| --- | --- |
| Nominal contract identity | `ContractRef.Key()` returns the shared `ContractKey` used by core registration and distribution. Kind/name/version have one grouping definition; native/portable implementations must agree on the same exact reference. |
| Durable Use request invariants | `UseApproval.Validate()` owns request validity. Host and Store invoke it at their boundaries; Store alone compares the current epoch. |
| Redundant attempt epoch column | Removed `frame_attempts.epoch`; the encoded admitted Attempt already owns that fact. No reader used the duplicate column. |
| Distribution responsibilities | Split the large Store file by import, publication, staging, verification, leases, collection and bounded file reads within the same package. Store ownership and APIs remain direct; no new service/repository/facade layers were added. |
| Work and settlement ownership | Moved interval behavior to `work.go` and protected-use settlement to `use_settlement.go`, retaining their existing aggregate and synchronization boundaries. |
| Browser publication lifecycle | Extracted `PublicationReceipt` and its terminal view into `publication.ts`, with shared identity predicates in `identity.ts`. Runtime retains its shared connection-revision orchestration and indexes. The runtime file shrank from 1,499 to 1,346 lines without creating a forwarding service. |
| Immutable JSON projection | Shared `freezeJSON` replaces duplicated browser/Node freeze code. Bounded Node admission still captures and budgets before retaining a schema. |
| Archive path states | `pathEntry` uses `fileEntry`, `directoryEntry` or `ancestorEntry`; the former kind-plus-explicit combination could represent an implicit file, which has no valid meaning. |
| Manifest lock construction | Removed a redundant serialize/parse round trip after constructing the valid lock from its validated manifest. The model already owns the invariant. |
| Schema traversal state | Replaced unexplained byte values with a private `schemaVisitState` and named states. |
| Entry limit naming | Renamed `Limits.Files` to `Limits.Entries`, with no compatibility alias, because directories and implicit ancestors count. |
| Comments | Removed narrative comments that restated names or operations. Kept tool directives, ownership/concurrency contracts, failure semantics, algorithm rationale and concrete SDK/OS pitfalls. |

## One fact, one owner assessment

| Fact | Transition authority | Allowed projections and their limits |
| --- | --- | --- |
| Completion of an admitted interval | One `workInterval`, guarded by its Lifetime | Any number of Work handles observe that interval; none has an independent finished flag. |
| Use release | Original Use Lifetime, followed by its original durable settlement | Resource handles, diagnostics and stored proofs observe the same release; cancellation never manufactures proof. |
| Direct child exit | Runner's original child Wait and exit receipt | Daemon callers and Store handoff retain that receipt; a later Close only advances original shutdown. |
| Business outcome | Original application/business record | Framework exit evidence does not decide whether the business operation succeeded. |
| Approved protection request | Original admitted Attempt/UseApproval | SQLite request bytes and digest must decode together before every read or transition that relies on them. |
| Artifact identity | Validated manifest declaration | A physical file snapshot proves bytes and executable mode for the same opened file; a cache hit does not redefine either. |
| Portable schema value | One bounded captured descriptor | Frozen declaration, compiler input and digest derive from that value; getters are not reread as fresh authority. |
| Browser output wire contract | Go control declarations and one control encoding policy | TypeScript types and executable decoders are generated projections, not a parallel schema. |
| Nominal contract grouping | `ContractKey` | Registries and distribution indexes consume the key; they cannot define a different grouping. |

A map, cache, wire DTO or generated file is not automatically a second owner.
It becomes one when it can originate a competing transition. The review
distinguishes lookup indexes from authorities and separate facts from duplicate
flags. For example, preparation completion and requested retirement are
independent facts; collapsing them would create illegal lifecycle states.

## Requested smell indicators

| Indicator | Audit disposition |
| --- | --- |
| Implicit coupling | Fixed SDK/Go output-shape assumptions, multi-read schema identity and decoder paths that silently omitted stored integrity. Existing explicit Host/admission/store authority matching remains. |
| Layer-first folders | Core and adapters are organized by domain/protocol. No controller/service/repository matrix was introduced. Distribution splitting remains within its real package. |
| Duplication | Removed copied Work completion, duplicate same-Lifetime Use registration, duplicated nominal-contract key, unused stored epoch and repeated protection validation paths. Generated protocol projections stay generated. |
| Representable illegal states | Invalid proof/state pairs, self-parent attempts, malformed Use identities, typed-nil adapters and unrepresentable program text are rejected at their owning boundary. Public wire DTOs remain data; construction and decoding validate before authority is granted. |
| God files | Distribution mixed several independently changing concerns and was split. Work, settlement and browser publication receipts now have focused files. Runtime's remaining indexes share one revision and admission boundary; file length alone is not evidence that this cohesive aggregate needs a new layer. |
| Shotgun surgery | Field/enum/output changes flow from existing Go declarations into generated SDK checks. Artifact verification and durable request admission have one policy owner per fact. |
| Layering violations | Root remains independent of process/MCP/browser product behavior. Qimu-specific contracts remain in optional `process/mcp`; business tasks remain in examples/application owners. |
| Pass-through wrappers | Removed the redundant lock round trip. Lifecycle/admission adapters that enforce a real guarantee are retained; moving them away would remove a boundary rather than simplify it. |
| Errors and validation away from the boundary | Moved identity/program/adapter checks before preparation or reservation; strict JSON precedes SDK decoding; response shape checks precede result acceptance; durable integrity precedes idempotent success or mutation. |

Behavior-rich types are used where they own invariants (`Work`, `UseApproval`,
`Attempt`, `Artifact`, contract objects and their captured schemas). DTOs are not
turned into empty accessor classes. Composition continues to combine admission,
Lifetime, original runner evidence and durable protection; no inheritance tree,
generic orchestration layer or new dependency was added.

Named protocol vocabularies, limits and schema profiles remain at their domain
owners. SQL text, user-facing error text, literal test inputs and centrally owned
schema tables are not replaced with arbitrary constants solely to eliminate
string literals. A map that declares an explicit domain grammar is different
from an untyped service bag or a second policy registry.

## SDK and dependency checks

The review used the pinned installed sources and repository manifests, not an
assumed latest API. The MCP syntax fix was checked against Go 1.27.3's JSON
implementation and the pinned `github.com/Tangerg/go-sdk` decoding path. Managed
MCP `MaxResponseBytes` initially looked conflated between stream chunks and final
results; the pinned Qimu backend applies that same policy to both, so it was not
changed speculatively. Runner tests preserve empty-environment semantics and
exact program text. Browser responses use generated checks from existing Go
models. SQLite fixes preserve original transaction/connection ownership and do
not replace modernc cleanup evidence with application guesses.

Primary comparison for the managed-stream policy:
[Qimu backend at 8027bd7](https://github.com/Tangerg/flame/blob/8027bd71390662b9365cadcbfb32c84f4826251d/qimu/mcp/backend_stream.go).
No dependency version was upgraded as part of this audit.

## Intentional contract changes

- `distribution.Limits.Files` is replaced by `Entries`; update callers directly.
- The unused `frame_attempts.epoch` column is removed. Existing schema mismatch
  detection requires a fresh development database; no migration or compatibility
  path is supplied.
- Browser success bodies must match their declared output shape. Void
  acknowledgements use null on the wire. Empty arrays are emitted consistently.
- MCP JSON with duplicate members or invalid escaped surrogate text is rejected
  before SDK interpretation.
- Runner paths, arguments and environment entries must be valid UTF-8 without
  NUL, and the overflow-prone executable limit is refused before authority setup.
- Corrupted or semantically incomplete protection records cannot be reused or
  released. Recovery must settle the original facts, not normalize bad records
  into apparent success.

These changes repair invalid contracts during development. No legacy aliases,
best-effort decoding, silent repair, automatic mutation retry or migration layer
was added.

The focused test counts in contributor notes overlap; they are not summed into
the final 263-test SDK total. An early broad Go diagnostic was taken while new

On a machine with Unix sockets and the pinned browser available, the remaining
repository gates are the complete race suite, the process example/conformance
paths, the real Chromium workflow and the separately configured Flame interop
workflow. This audit reviewed the pinned Flame protocol source and integration
scripts, but does not claim a completed full Flame integration run. No platform
matrix, benchmark campaign or exhaustive filesystem/concurrency schedule
exploration was performed.

This audit reports concrete findings and the scope of verification. It does not
prove the absence of every possible defect, establish a performance ranking, or
claim standard-library-level quality from file counts and test totals alone.
